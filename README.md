# Vitamin Village — iOS app

The web version of Vitamin Village (served from the storefront repo at
`1084.github.io/vitamin-village`) wrapped as a native iPhone app with
[Capacitor](https://capacitorjs.com), plus what the App Store version adds:

- **Haptics**: a tap when a new buddy pair is discovered, a success buzz when the
  badge book is complete (`native/native.js`, via `@capacitor/haptics`).
- **Persistent progress**: badges survive closing the app. Saved on-device only.
- **No service worker, no network, no data collection.** Everything is bundled.

The game file itself is *not* edited here. `npm run prepare-www` copies it from the
storefront repo, removes the service-worker registration, and appends the native
bridge. Fix the game in one place (the storefront repo), then rebuild.

## Layout

```
capacitor.config.json     app id, name, web dir
native/native.js          haptics + persistence bridge (appended to index.html)
scripts/prepare-www.mjs   builds www/ from the storefront's vitamin-village folder
resources/                AppIcon-1024.png, PrivacyInfo.xcprivacy (copy into Xcode)
www/                      generated — do not edit, do not commit
ios/                      generated by `npx cap add ios` — commit this
```

## One-time setup on the Mac

Requirements: macOS with **Xcode** (App Store, free, large), **Node 20+**, and
**CocoaPods** (`sudo gem install cocoapods` or `brew install cocoapods`).

```bash
# 1. Have both repos side by side
cd ~/Documents
git clone https://github.com/1084/1084.github.io.git      # already there if you built the site
# (this repo)  ~/Documents/vitamin-village-app

# 2. Install and create the iOS project
cd ~/Documents/vitamin-village-app
npm install
npm run prepare-www                 # builds www/ from ../1084.github.io/vitamin-village
npx cap add ios                     # creates ios/  (one time only)

# 3. Copy the App Store resources into the Xcode project
cp resources/PrivacyInfo.xcprivacy ios/App/App/PrivacyInfo.xcprivacy

# 4. Sync web files + plugins into the iOS project, then open Xcode
npx cap sync ios
npx cap open ios
```

In Xcode, once:

1. **Signing & Capabilities** → Team: your Apple Developer account. Bundle id is
   `com.vitaminvillage.app` (change it in `capacitor.config.json` *before*
   `cap add ios` if you want a different one; changing later is painful).
2. **Assets.xcassets → AppIcon**: drop `resources/AppIcon-1024.png` into the
   1024×1024 slot. Xcode generates the rest.
3. **General → Deployment Info**: iPhone only, Portrait only (matches the web
   app's manifest). Minimum iOS: leave the Capacitor default.
4. **Info** tab: add `PrivacyInfo.xcprivacy` to the App target if Xcode didn't pick
   it up automatically (File → Add Files to "App").
5. Pick a simulator or your plugged-in iPhone and press Run. On a real phone,
   discovering a buddy pair should buzz.

## Every time the game changes

```bash
cd ~/Documents/1084.github.io && git pull       # get the latest web version
cd ~/Documents/vitamin-village-app
npm run sync                                    # prepare-www + cap sync ios
npx cap open ios                                # build / archive in Xcode
```

Bump the version in Xcode (General → Version and Build) before each upload.

## Submitting to the App Store

1. **Apple Developer Program** ($99/yr) at developer.apple.com. Individual enrollment
   shows your legal name as the seller; only an organization (legal entity +
   D-U-N-S number) can show a company name. Approval takes ~48 hours.
2. **App Store Connect → My Apps → +**: name "Vitamin Village", bundle id as above,
   SKU anything (e.g. `vitaminvillage1`).
3. **Archive** in Xcode (Product → Archive, with "Any iOS Device" selected) →
   Distribute App → App Store Connect → Upload.
4. **TestFlight** first: add yourself and a few families as internal/external
   testers. This is the cheapest way to catch device-specific problems.
5. **App Store listing**: screenshots (6.9" and 6.5" iPhone sizes are required; take
   them in the simulator with ⌘S), description, keywords, support URL
   (`https://1084.github.io/`), privacy policy URL (required — a short page saying
   the app collects nothing; add one to the storefront).
6. **App Privacy** questionnaire: answer *Data Not Collected*. That is true and
   it's the strongest position a kids' app can be in.
7. **Age rating**: answer the questionnaire honestly; it will come out 4+.
8. **Kids Category** decision: opting in gives visibility in the Kids section but
   is permanent and forbids any third-party analytics or ads, ever, plus no
   outbound links. Vitamin Village already complies. Read `shipping_roadmap.md` in
   the VIG repo before deciding; it can't be undone.
9. **Review notes**: state that the app is fully offline, bundles all content, and
   uses native haptics; that pre-empts the "just a website" (guideline 4.2) question.
10. Submit. First reviews typically take 1–3 days; rejections come with a reason
    and you resubmit.

## Privacy, in one line

Vitamin Village collects no data, uses no analytics, contacts no server, and saves
badge progress only on the device. `resources/PrivacyInfo.xcprivacy` says exactly that
in the format Apple requires. Keep it true.
